🧱 SSEA v1 — Single Source Execution Authority

Версия: 1.0
Назначение: Единый контур управления анализом, проектированием и исполнением в системе «Пигмалион / К.Р.И.С.Т.А.Л.Л.»
Принцип: Один агент — одна фаза — один тип истины

1. 🧭 Цель SSEA

SSEA вводит строгую дисциплину исполнения:

устранить смешение аудита, проектирования и исполнения между агентами

и гарантировать:

детерминированность решений
отсутствие скрытых изменений
трассируемость через acts_log (SSOT)
контроль переходов фаз
2. ⚙️ Единственная модель исполнения
📌 State Machine

Любой агент может находиться только в одном состоянии:

AUDIT → PLAN → EXECUTE → VERIFY

Переход возможен только через явное разрешение человека.

❗ Жёсткое правило

Никакой фазовой интерпретации агентом

Фаза задаётся внешне, не выводится из контекста.

3. 🧠 Роли агентов
🟦 Jules — Engineering Executor

Разрешено:

изменения кода (только EXECUTE)
тесты
PR
CI fixes

Запрещено:

архитектурные решения
расширение scope
оптимизации без задачи
🟨 CodeGPT — Local Wiring Assistant

Разрешено:

локальный анализ
подсказки по коду
технический разбор

Запрещено:

изменение архитектуры системы
управление фазами
формирование canonical решений
🟪 NotebookLM / Architect Agent

Разрешено:

архитектурные предложения
ADR (Decision Records)
анализ альтернатив

Запрещено:

выполнение кода
прямые изменения системы
интерпретация SSOT
4. 📡 Single Source of Truth (SSOT Rule)
Единственный источник истины:
acts_log

Правила:

все состояния восстанавливаются только через Replay
никакие промежуточные слои не являются истиной
любые projections = временные
5. 🔒 Phase Gate (ключевой механизм)
Переходы строго контролируются:
AUDIT → PLAN

Требуется:

явное разрешение человека
PLAN → EXECUTE

Требуется:

“Plan approved”
EXECUTE → VERIFY

Требуется:

завершение изменений
прохождение тестов
❗ Запрещено:
автоматический переход между фазами
смешение фаз в одном ответе
“частичный execute во время plan”
6. 🚫 Forbidden Behaviors (глобальные)

Любой агент не имеет права:

выполнять изменения вне своей фазы
совмещать audit + execute
предлагать изменения “по пути”
создавать скрытые архитектурные решения
модифицировать SSOT (acts_log)
расширять scope задачи
7. 🧩 Execution Integrity Rules
Rule 1 — No Silent Execution

Любое изменение = только в EXECUTE фазе

Rule 2 — No Silent Architecture Drift

Архитектура фиксируется только в PLAN и после approval

Rule 3 — No Mixed Outputs

Ответ агента должен быть строго одного типа:

AUDIT report
PLAN document
EXECUTION diff
VERIFY report
8. 📊 Output Contracts
🟦 AUDIT OUTPUT
- findings
- gaps
- risks
- missing info

❌ no fixes

🟨 PLAN OUTPUT
- proposed changes
- affected files
- dependencies
- risk analysis

❌ no code execution

🟥 EXECUTE OUTPUT
- file changes
- commits
- PR

❌ no architecture decisions

🟩 VERIFY OUTPUT
- test results
- replay status
- mismatch report
9. 🧭 Canonical Constraint Layer

SSEA не заменяет Canon.

При конфликте:

CANON.md > SSEA > agent instructions
10. 🔁 Replay Rule

Любое состояние считается валидным только если:

восстановимо из acts_log
проходит Replay Test
не зависит от agent memory
11. 🧯 Conflict Resolution Rule

Если агент получает противоречивые инструкции:

остановка
report conflict
ожидание человека
никаких действий
12. 🧱 System Outcome

После внедрения SSEA:

Jules перестаёт “дрейфовать в execution”
NotebookLM перестаёт “влиять на исполнение”
CodeGPT перестаёт “архитектурить систему”
появляется чистый pipeline
Human → AUDIT → PLAN → EXECUTE → VERIFY → acts_log
13. 🧭 Ключевая идея SSEA

не управлять агентами через “умные промпты”,
а через жёсткое разделение фаз реальности
