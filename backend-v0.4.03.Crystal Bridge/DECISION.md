# DECISION REGISTER - v0.4.03 "Crystal Bridge"

## Обзор

Этот регистр фиксирует архитектурные решения, принятые в Crystal Bridge.

Это не история — это сводка решений.

## Decision 01 - Crystal Bridge

Название рабочей директории:

`backend-v0.4.03.Crystal Bridge`

Статус:

DECISION / Архитектурный принцип.

Версия:

Переходная версия между релизами.

## Decision 02 - Неприкосновенность артефактов

CANON, acts_log, Replay, SQL, Docker, package.json и исходный код — неизменяемы в Crystal Bridge.

Статус:

ARCHITECTURAL PRINCIPLE.

## Decision 03 - Preview → Confirmation → Execute → Replay

Все архитектурные решения проходят 4 стадии.

Статус:

GOVERNANCE RULE.

## Decision 04 - canonical-glossary-v0.5.md

`canonical-glossary-v0.5.md` выступает как глоссарий терминов/версий для v0.5.

Он становится частью CANON после утверждения и включает:

- 1111 терминов;
- Единый язык домена;
- Версионирование артефактов;
- Состояния жизненного цикла;
- Зависимости v0.5.

Статус:

STD-05 / Версионный стандарт.

Он не входит в CANON до утверждения.

## Decision 05 - MCP

MCP остаётся открытым архитектурным вопросом для Crystal Bridge.

Статус:

OPEN ARCHITECTURAL QUESTION.

## Decision 06 - Лексер

Файл `лексер.txt` с исходным кодом является SOURCE MATERIAL.

Перенос лексера требует верификации совместимости версий.

Необходима обратная совместимость `threshold.js` / `threshold-canonical.js` и API.

## Decision 07 - Execution boundary

Исполнение разрешено только для Markdown-артефактов в рамках решений.

Любые изменения проходят Audit → Plan → Approval.

============================================================
EXECUTION BOUNDARY
============================================================

Allowed:

- Создание Markdown-артефактов;
- Чтение и анализ файлов;
- Планирование миграции / архитектуры;
- Верификация артефактов без изменения.

Forbidden:

- Создание кода;
- Изменение существующих файлов;
- Запуск тестов;
- Коммиты;
- Изменение Docker-конфигурации;
- Изменение SQL;
- Подключение к PostgreSQL;
- Изменение package.json;
- Деплой;
- Изменение CANON.md;
- Изменение acts_log;
- Изменение Replay;
- Изменение инфраструктуры.

Процедура проверки:

1. Создать все 4 Markdown-файла.
2. Проверить содержимое.
3. Выполнить `git diff --` для подтверждения, что только 4 файла добавлены.
4. При отсутствии изменений — передать на ревью.
